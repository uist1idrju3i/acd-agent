## 3. GUI会話（L2）の分析

会話eventは331件で、内訳はhook 123件、state update 77件、action 64件、observation 62件、
user message 2件、hook拒否 2件、system prompt 1件である。

- **hook**: `SessionStart` 1件（ok）、`PreToolUse` 118件（うち2件がblock）、`Stop` 4件（ok）。
  block 2件はいずれもprojection保護hookで、理由は
  「Derived projections are regenerated by the pipeline; edit design inputs (graph.json / profiles) instead.」である。
  **GUI経路でもprojection保護は実効していた。**
- **tool登録**: 会話のToolDefinitionは`terminal`、`file_editor`、`task_tracker`、
  `canvas_ui_control`、`launch_child_conversation`のみで、`acd_*`は存在しない。
  agentはcommand契約どおり`verify_acd_tool_registration.py`でtool不在を確認し、
  任意shellへ流れずに宣言済みCLIへ退避した。T-3（入口へ到達できない）は退避経路としては
  改善したが、`acd_*` tool経路そのものは未達である。
- **host実行の失敗**: 会話はまずhostで`run_design_loop.py`を起動し、`silkscreen-resolve`段で
  `FileNotFoundError: '/usr/share/kicad/symbols/power.kicad_sym'`によりfail-closedした。
  その後`run_in_workspace.py`へ切り替え、digest固定imageを明示してcontainer内で完走させた。
- **資材持ち出し**: 途中でagentは(1) hostへの`sudo apt-get install kicad-symbols`（sudo不許可で失敗）と
  (2) container内の`/usr/share/kicad/symbols`・`footprints`をhostの`/tmp`へtarで取り出す操作を試み、
  (2)は成功した。最終的にcontainer実行へ倒れたためEvidenceの権限境界は守られたが、
  「hostへEDA資材を持ち出す操作」自体はhookで止まっていない（V-1）。
- **報告文面**: 会話の最終報告は「loop completed successfully／pre-order gate PASSED／ready for order」
  だが、根拠はcontainerのstdoutと`gui/loop-summary.json`・`gui/timing-record.json`
  （いずれも`pass_evidence: false`）だけである。会話はEvidenceをdownloadせず、
  製造提出判定もEvidence検証も実行していない。**L3観測を合格の言明へ昇格させる報告になっている（V-3）。**

### 4.1 GUI経路とCLI経路の所要時間（13.7の記述に対する訂正）

`timing-record.json`の`stages[].duration_seconds`は26 stageの**合計**であり、lane並列のため
wall-clockより大きい。同じ指標で比較すると次のとおりである。

| 経路 | timing-record合計 | wall-clock |
|---|---:|---:|
| GUI会話のcontainer実行 | 495.2秒 | 未計測（会話往復を含むため定義困難） |
| Run N（CLIから直接） | 473.4秒 | 259秒 |

13.7は「GUI 495.2秒 対 CLI 248秒」と並べているが、これは合計値とwall-clockの比較であり、
2倍近い差はオーバーヘッドではない。同種の指標では差は約4.6%であり、
**GUI経路のcontainer実行がCLI実行より大幅に遅いという記述は成立しない。**
13.7の当該記述は訂正が必要である（本PRで訂正した）。

## 5. 未達理由（acd-agent単体でのVibeBB成立）

1. 新規specがsilkscreen宣言不足でfail-closedし、GD1以外は基板laneへ到達しない（V-6）。
2. GUI会話は`acd_*` tool未登録のままCLI退避で走っており、command宣言の入口を満たしていない（T-3残）。
   さらに最終報告がL3記録だけで合格・発注可を述べる（V-3）。
3. 却下からの復帰（T-1）は本検証の対象外であり、依然として未観測である。

自動発注と実機測定はscope上の将来機能・非対象であり、未達理由には含めない。

## 6. 収録物の解釈上の注意

- `board/`・`enclosure/`・`firmware/`は「発注可能な品質」を主張する成果物ではなく、
  `loop/manufacturing-submission.json`が示す8項目の決定論的判定に通った状態のデータである。
  実際の製造可否は製造業者のDFM判断に従う。
- `board/kicad-netclass-positive-control/`はnetclass設定を故意に崩したnegative/positive control出力であり、
  設計成果物ではない。
- `firmware/flash.bin`はQEMU上で起動確認した仮想実行の対象であり、実機での動作確認は行っていない。
- `silkscreen/`と`newspec/mini-blink-dongle-silkscreen-resolve/`のwork-fixtureは
  pipelineが生成した中間入力であり、`fixtures/`の設計入力を置き換えるものではない。
