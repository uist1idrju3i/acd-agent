# 設計フロー

> ステータス: Draft

入力ファイルとgitを正とし、各工程の成果物を機械可読投影または視覚投影として生成する。
投影は入力へ逆流させない。LLMは要件、修正方針、レビュー所見を扱い、決定論的スクリプトと
ゲートが成果物の合否を決める。

## 工程

| ID | 工程 | 主な入力・出力 |
|---|---|---|
| S1 | 要件対話 | 自然言語要件、禁止事項、対象部品 |
| E1 | 部品・回路 | 回路入力、部品表、ピン割当 |
| E2 | アートワーク | PCB、配置、配線、Gerber |
| M1 | 筐体コンセプト | 外形、開口、締結、材料 |
| M2 | 筐体詳細 | STEP/3MF、肉厚、干渉、組立性 |
| S2 | 製造出力 | Gerber、drill、BOM、CPL、筐体出力 |
| S3 | 製造・加工 | fab所見、造形・切削所見 |
| S4 | 試作立ち上げ | 実機テスト、測定値、次の修正 |

## 投影レビュー

各工程で機械可読投影と視覚投影を生成し、`AgentDefinition`で分離したsubagentとvisionへ渡す。
所見は自然文で修正ループへ返す。LLMレビューは合否権限を持たない。

## 決定論的ゲート

- ERC/DRCを実行する。
- 生成経路とは別parserで成果物を再読込する。
- 筐体はgeometryの有効性、干渉、外形、肉厚を検査する。
- FWはビルド、静的解析、単体テスト、ピン割当整合、ログ期待値を検査する。
- 外部ツールの不在、parse失敗、ゲート未実行、安全境界の`unknown`は停止する。

変更後は入力ファイルを修正してgitへ記録し、全ゲートを再実行する。発注直前にも全ゲートを
実行し、設定上限額以内であることと合わせて確認する。

## 安全境界

安全境界の設定は`profiles/`配下のcommitだけで変更する。会話や投影から安全境界を変更しない。
AC電源、高電圧・大電流、レーザー、医療・車載、無線送信、Li-ion/LiPo充電は初期対象外とする。
