# ADR-0007: 配置・回転・配線探索へのLLM適用境界

> 追補: ADR-0008により、探索仕様の機械可読契約と探索固有Evidenceは現行要求から外した。決定論的な候補生成・合法化、代理指標による順位付け、少数候補の実測を残す。
> 追補: ADR-0009により、「LLMに座標・回転角を直接出力させない」は撤回した。LLMが座標・回転角を直接提案してよく、提案は入力ファイルへ確定したのちにACDの投影と決定論的ゲートで判定する。探索器と代理指標の採点はACD本体ではなく`plugins/acd/skills/`のSkillが持つ。

> ステータス: Accepted
> 日付: 2026-08-16
> 関連: [`../research/ai-physical-design.md`](../research/ai-physical-design.md)、[`../research/prior-art.md`](../research/prior-art.md)、[`../roadmap.md`](../roadmap.md)、[`ADR-0003-sdk-feature-adoption.md`](ADR-0003-sdk-feature-adoption.md)、[`ADR-0010-plugin-first-openhands-integration.md`](ADR-0010-plugin-first-openhands-integration.md)

## コンテキスト

`E2`アートワークの配置・回転・配線は、位置・回転角・外形・シルク占有・クリアランス・
配線可能性・製造制約が相互依存する組合せ探索である。先行実装では、候補ごとに
「fixture再生成 → 外部router → `kicad-cli` → Gerber実測」というフルパイプラインを
回したため、探索コストが候補数に乗算されて閉じなかった。加えて、下流（シルク配置）で
探索を続けても、原因が上流（配置・外形）にある場合は解に到達しなかった。

一方で、LLMに座標・回転角を直接生成させる案には次の問題がある。配置・制約推論を扱う
公開benchmarkは現行LLMが実務水準に届いていないことを示す。また内側ループでLLMを呼ぶと、
反復コストが候補数に比例して予算と打ち切りを宣言できなくなり、失敗原因を探索仕様へ
帰属できない。なお、毎回同じ設計が出ることは要件でない。要件は、各候補に設計根拠が
紐づき、記録した仕様・seed・ツール版・入力hashからEvidenceを再測定できることである。

研究・商用の先行事例も、LLMを制約生成・優先順位付け・戦略選択に使い、幾何の生成と検証は決定論的アルゴリズムと物理検証に任せる構成が主流である
（[`../research/prior-art.md`](../research/prior-art.md)の§21）。

## 決定

配置・回転・配線の探索を、宣言・探索・判定の三層に分離する。

1. **宣言層（LLM）**: LLMは探索仕様（モジュール分解、相対配置制約、優先度、回転刻み方針、
   探索戦略、評価方針、緩和提案）と設計根拠を出力する。座標・回転角を直接提案してもよい
   （ADR-0009）。ただし提案は候補であり、合格根拠にはならない。
2. **探索層（決定論）**: 探索仕様をコンパイルし、seed固定の局所探索と幾何整合化で
   候補を生成し、代理指標で順位付けする。内側の探索ループでLLMを必ず呼ぶ構成は既定にしない。
3. **判定層（決定論的ゲート）**: 代理指標上位の少数候補にのみ外部router、ERC/DRC、
   Gerber独立再読込を実行し、合否は決定論的ゲートだけが決める。

あわせて次を決定する。

- 回転刻みの許容範囲は`profiles/`配下の版管理された宣言を正とし、90度刻みを既定として
  段階的にのみ緩和する。LLMは方針と根拠を提案するが、許可はprofileとEvidenceが与える。
- 視覚投影のレビューは問題の発見に使い、合否根拠にしない。`ReviewFinding`は根拠の引用を必須とする。
- 所見ごとの機械可読な再測定は必須にせず（処分と理由の記録のみ必須）、実測とstale検出を
  出口ゲート（`RV2`、DRC/ERC、Gerber再読込、DFM、発注前最終ゲート）へ集約する。
  これによりLLMの反復を安く回し、記録の重さを出口へ寄せる。未処分の重大findingで`RV2`を
  通さないことと、stale Evidenceを合格根拠にしないことは維持する。
- 無人ループには停止条件（探索仕様hashの再提出、連続非改善、同一finding再発、予算超過）を
  宣言し、いずれもfail-closedで止める。
- 配線はLLMにトレースを引かせず、配線順序・層割当・netclass・router設定というメタ制御と、
  配線不能原因の帰属提案に限定する。ヒューリスティックのコード生成を試す場合は、
  生成物をリポジトリへcommitし、通常のlint・型検査・テスト・golden task回帰の対象とする。

## 検討した代替案

| 代替案 | 却下理由 |
|---|---|
| 内側の探索ループでLLMを既定にする | 幾何の可否は数値精度に依存し、修復の往復回数が予測できない。benchmarkの実力値も不足しており、予算と収束を宣言できない（LLMが座標を提案すること自体はADR-0009で許容した） |
| 探索の内側ループでLLMに次の候補を選ばせる（LLM as optimizer） | token・money・wall-clockが候補数に比例し、予算と打ち切りを宣言できない。研究例はあるが、失敗原因を探索仕様へ帰属できなくなる |
| 強化学習で配置・配線モデルを学習する | 学習環境・計算資源・データが初期ターゲットの範囲外。既存routerを借りる原則にも反する |
| 従来どおり決定論的アルゴリズムのみで探索し、LLMを使わない | 設計根拠・データシート・要件からモジュール分解と優先度を作る部分が人手依存のまま残り、無人ループが閉じない |
| 90度刻みを全面的に撤廃し、連続角度を既定にする | CPL回転規約、実装機精度、検査性への影響を実測していない。撤廃はprofileとEvidenceに基づく段階的緩和として扱う |
| stale判定も外してLLM主導にする | 不可逆点は発注（金額と納期）であり、古い外形や差し替え前footprintの成果物で発注が通る。損失が非対称なため、所見の再測定は緩めてもstale検出は残す |

## 影響

- `docs/research/ai-physical-design.md`が探索方針の正となり、[`../roadmap.md`](../roadmap.md)に
  当該フェーズを追加する。
- 探索仕様のschema正本の所在（設計グラフnodeか独立契約か）は未決であり、フェーズ着手時に確定する。
- `E2`の実装は、探索器・整合化器・代理指標を生成側モジュールへ、実測とゲートを判定側モジュールへ
  分ける（[`../architecture.md`](../architecture.md)の生成と判定の分離）。
- 予算次元（反復、wall-clock、token、money、外部process回数）を探索ゴールデンタスクで実測する。

## 未確認・リスク

- 代理指標と実測結果の相関はACD内で測定していない。相関が弱い場合、L2からL3へ送る候補数を
  増やす必要があり、コスト見積が変わる。
- LLMが探索を実際に改善しているかは、LLMなしの既定探索仕様との対照実験でしか判定できない。
  この対照条件を用意するまで、改善効果を主張しない。
- 商用AI配置・配線の構成はベンダー主張であり、独立に再現検証していない。
