# ECAD領域知識と投影契約

> ステータス: Draft
> 対象: KiCadを含むECADツールを外部プロセスとして駆動するACDの投影・検証・再現性契約

本書は、ECADプロジェクト、回路意図、ライブラリ、ルール、幾何、製造出力を
ACDの設計グラフから投影するときの契約と、既知の落とし穴チェックリストを正とする。
工程IDは[`glossary.md`](glossary.md)、工程ごとのゲートは
[`design-flow.md`](design-flow.md)、ツール採否と一次確認事項は
[`tool-selection.md`](tool-selection.md)、フェーズ境界は
[`roadmap.md`](roadmap.md)を参照する。

本書の「ACDの扱い」は設計方針・不変条件であり、特定ツールの挙動を保証しない。
ツール依存の事項は「Phase 0の能力プローブ候補」として一次確認し、確認できない場合は
`unknown`で停止する。

## 1. プロジェクトとファイルの境界

ECADプロジェクトは、プロジェクト設定、回路意図、基板、ライブラリテーブル、ローカル
ライブラリ、再利用ブロック、出力設定などのファイル群と解決済み参照からなる投影単位である。
一部のファイルだけを持ち出して整合を仮定しない。

**ACDの扱い：**

- 投影を単一ファイルではなく「ファイル集合＋解決済み参照」として扱い、集合の構成、
  実パス、版、commit、入力hashをEvidenceへ記録する。
- 生成物、自動バックアップ、キャッシュ、ロックファイルは通常の設計投影集合から除外する。
  ロックファイルの存在は外部エディタまたは別プロセスとの競合を示すシグナルとして扱い、
  adapterは上書き・切替の前に停止または解決を要求する。
- 相対参照、環境変数、ライブラリテーブルの入れ子参照を暗黙の前提にしない。adapterは
  解決後の実パス、ライブラリ版、commitを記録し、解決不能なら`unknown`で停止する。
- 生成物を保存するリポジトリでは、自動生成物と一時ファイルをignoreし、OS間の改行・文字コード
  差異を属性設定で扱う。ignore設定そのものも版管理された実行条件とする。

## 2. 版と設定の固定

ツール版、ファイル形式版、プロジェクト設定、実行環境が決定論の前提である。ファイル形式の
非互換更新や再保存の挙動はツール依存であり、ACDの既定動作として仮定しない。

**ACDの扱い：**

- 投影の生成・再読込は固定したツール版と形式版の経路で行い、両方をEvidenceへ記録する。
  版が混在した投影、形式版が不明な投影、再読込できない投影は合格にしない。
- Phase 0で、より新しい版による形式更新、旧版での再読込、再保存時の差分、形式版の
  非可逆更新が起きるかをfixtureで確認する。確認前はリビジョン復元に旧生成物を使わない。
- ユーザー単位の設定とプロジェクト単位の設定を分離し、adapterは固定した設定ディレクトリ、
  パス変数、言語、単位を明示して実行する。グローバル設定への暗黙依存を許可しない。
- 設定破損からのリセットは復旧手段として記録するが、既定経路を設定破損に依存させない。
  設定ディレクトリの隔離、初期化、再現方法を実行記録に含める。
- GUI部分と処理backendが別配布・別インストールになる候補は、プラグインとbackendの版、
  入出力、互換性を個別にpinする。本体の更新による互換性はPhase 0で確認し、確認前は
  一次経路にしない。
- ヘッドレス環境ではGPU・表示サーバを前提にしない。描画・3Dレンダリングを使う場合は
  レンダラ種別、表示依存、解像度、画像hash、visionレビューへ渡したprofile／model、
  代替の非描画経路をEvidenceへ記録し、既定ゲートを描画非依存にする。視覚投影は
  `ImageContent`または`inspect_image_with_vision`へ渡せるが、描画結果をゲートの正にしない。

## 3. 回路意図とnetlist投影

ネット同一性は、直接接続、ラベル、階層ポート、グローバル名などの投影表現ではなく、
設計グラフの接続edgeで決まる。名前解決や省略表記を接続の正としない。

**ACDの扱い：**

- グラフ側で個別ネットの安定identifierと接続関係を保持し、投影時にネット名・ラベルを生成する。
  同名だから接続するという逆向きの推論は行わない。
- バスや複数信号の一括表現は展開規則と展開結果を記録する。展開後の個別ネットを正とし、
  投影側の省略表記に未記録の意味を持たせない。
- 階層シートでは、親のポート、子の対応ラベル、インスタンスパスを別のnodeとして持つ。
  同一定義を複数インスタンスから参照する場合、定義側の変更は全インスタンスへ影響し、
  識別子・採番などのインスタンス固有属性は個別に管理する。
- 部品シンボルのピン電気種別、電源供給の意図、意図的な未接続、意図的な単一駆動源を
  グラフ側の一次情報として持つ。明示は検査を黙らせるための細工ではなく、根拠付き設計判断
  として追跡する。検査除外は決定論的ゲートで扱う。
- 複数ユニット部品、代替ピン機能、論理等価な別記号形は、パッケージ、unit、pin、netを
  別nodeとして表現し、投影時の割当をEvidenceへ記録する。
- 内部ジャンパー、0Ω部品、重複ピン番号などの内部接続属性は、netlist投影と未接続判定の
  双方へ渡す。属性欠落は`unknown`で停止し、未接続判定を抑止した状態を合格にしない。
- variant／DNPは実装可否、値、型番、BOM・実装データ・シミュレーション対象可否を切り替える。
  外形、配置、配線はvariant間で共通とし、variantごとのartifactとEvidenceを固定する。
- 安定identifierとrefdesを分離し、refdes採番規則を決定論的に固定する。階層・反復構造では
  インスタンスパス単位の一意性を検査し、位置ベース再採番を正規化なしに許可しない。
- タイトル、改訂、日付、文書内テキスト変数はグラフから投影する。投影側の手入力を正にしない。

## 4. ライブラリ品質と検査の盲点

ERC／DRCなどの自動ゲートは、与えられた記述とルールの整合を判定する。ライブラリ記述や
設計意図の真偽を自動的に保証するものではない。ライブラリ品質は検査能力の上限である。

**ACDの扱い：**

- シンボルのピン番号・機能、フットプリントのパッド番号・寸法・ピッチ・位置、基準点／アンカー、
  極性・向き、3Dモデルの原点・姿勢・スケールをデータシート・寸法図と照合する。
- シンボルとフットプリントの接続根拠はピン番号とパッド番号の対応として記録し、名前や見た目を
  対応の根拠にしない。
- courtyardの有無・範囲、パッド単位とfootprint単位のマスク／ペースト属性、熱パッド、
  めっき無し穴、スロット、キャスタレーションをライブラリEvidenceへ含める。courtyardが
  不足する場合、干渉検査の対象範囲を狭めず`unknown`として停止する。
- 第三者提供、自動生成、形式変換、継承由来のライブラリは検証対象の入力とする。継承元の
  出所と差分を記録し、照合Evidenceなしに採用しない。
- 型番、データシート、メーカー、コスト、実装除外、BOM除外などのfieldはグラフの一次情報から
  投影する。投影側での一括編集を正にしない。
- 画像由来のシルク図形と外形のベクタ図形は、単位、スケール、原点、閉曲線性、単一輪郭性、
  位置合わせ用補助図形の残存を検査してから受け入れる。
- 3Dモデルの出所、版、パス変数解決、位置・回転・スケールoffsetをEvidenceへ含める。
  機械レーンの干渉判定は、3Dモデルの姿勢・offsetが未確認なら`unknown`とする。

## 5. ルールと制約の表現

**ACDの扱い：**

- 配線幅、クリアランス、ビア径・穴径、差動対の幅・gapは、設計グラフのnetclass／rule
  templateとして定義し、ネットへ割り当てる。領域指定（rule area／keepout）による局所適用も
  同じグラフ属性から投影する。
- 表形式で表せない条件はカスタムルールとして表現し、条件、重大度、対象範囲、版を記録する。
  重大度の引き下げや個別除外は合格根拠にせず、決定論的ゲートで扱い、
  承認状態を必須にし、既定では無効にする。
- router adapterへ同じnetclass・制約・領域条件を渡す。routerの完了報告を合格根拠にせず、
  出力を再読込して設計規則検査で実効を確認する。
- solverの実行時間、探索順序、非決定性、正規化可能な差分はPhase 0で実測する。規則外の差分は停止する。
- fab profileはテンプレート化された投影初期状態として版管理し、profile更新時の再検証範囲を
  impact analysisで導出する。
- 検査結果は合否だけでなく、ルールID、重大度、座標、対象要素、条件、入力・出力hashを
  機械可読なEvidenceとして保存する。形式と取得方法はPhase 0で一次確認する。

## 6. 幾何・派生状態・座標系

**ACDの扱い：**

- 銅ベタ（ゾーン）の塗りつぶし等は派生状態として管理する。外形、ルール、接続を変更した後は
  検証前に再計算し、未再計算の結果を合格にしない。
- ゾーンの優先順位、熱抜き、孤立島、パッドとの接続、分割条件をグラフ属性として記録し、
  投影後の再計算結果と照合する。
- 基板外形は閉じた単一輪郭として検査する。開いた輪郭、二重線、インポート由来の残骸を
  検出し、残存した状態で製造出力へ進めない。
- 単位、設計原点、穴・実装位置ファイルの原点、軸の向き、gridとpad中心の関係、footprint
  anchorとpad中心の関係を固定し、Evidenceへ記録する。内部幾何は固定小数点整数で保持し、
  grid snapを唯一の正にしない。
- 部品ピッチの基準系、配列の行列数・間隔・回転をグラフの規則として保持し、部品ごとの基準系
  から再生成する。
- ビア種別、stackup依存、pad内ビア、アニュラリング、最小穴径、マスク被覆（テンティング）
  方針をfab profileと突き合わせる。既定値依存が解決できない場合は`unknown`とする。
- 涙滴補強、配線コーナーの円弧化、外形コーナーの丸めは最終生成段階で適用する。適用後の
  投影を編集起点にせず、必要ならグラフから再生成する。
- stackup（層構成、基板厚、誘電体、銅厚、マスク／シルク）は電気・機械双方の入力であり、
  基板厚をM2へ明示的に渡す。寸法記入・測定・文書層は機械向け投影であり正ではない。

## 7. 製造出力

**ACDの扱い：**

- 層ごとの図形、穴、実装位置、部品表、基板仕様を別artifactとして管理し、単位、座標桁数、
  原点、面、軸向き、命名、属性付与をfab profileで固定する。
- 穴データはめっき有無、スロット、工具一覧、穴図・レポートを含め、図形データと原点を照合する。
- BOMはfield構成、grouping、除外flagの解釈を固定する。実装位置は面、回転基準、原点を
  固定し、回転基準の差異を独立検査する。
- 交換形式を採用する場合は形式版と対象範囲を記録し、形式ごとの独立再読込を用意する。
- 生成器とは独立した実装で図形、穴、数量、座標、層対応を再読込し、片方だけを合格根拠にしない。
- 図面、SVG、3D形状、ブラウザ閲覧形式はレビュー用投影であり、正ではない。レビューは
  観察の入力であって、合否は機械ゲートとEvidenceで決める。
- 外形、配線、穴、実装位置座標はvariant非依存、BOM、実装対象、DNP表示を含む検査用出力は
  variant依存とし、全artifactへvariantを固定する。

## 8. 面付け

量産・試作の面付けは、単体基板から別の製造用投影を生成する工程である。行列数、基板間隔、
連結タブ、Vカット／ミシン目、外周フレーム／レール、位置決め穴、フィデューシャル、識別表示、
タブ上の銅とクリアランス、工具半径、面付け後の外形処理を構造化する。

**ACDの扱い：**

- 面付けを`S2`製造出力の工程として扱い、パラメータを設計グラフまたはfab profileへ保存する。
- 面付け後のデータも投影とし、面付け後の投影から製造出力を生成する。
- 面付け後にDRCと独立再読込を実行し、面付け前のEvidenceを流用しない。
- 工具半径、タブ幅、切り分け方式、レール幅、基板間隔をfab能力と突き合わせる。
- 面付けツールのライセンス、版、CLI契約、互換性、ヘッドレス実行可否はPhase 0で一次確認する。

## 9. 交換と外部ツール境界

**ACDの扱い：**

- router交換はnetclass・ルールを含む入力と結果の境界として扱い、取り込み後に自前で再検証する。
- ECAD↔MCAD交換はboard only、部品・配線の有無、原点などの条件をartifact contractへ固定する。
  形状出力の成功を嵌合の合格とみなさない。
- シミュレーションのピン順とモデルnode順の対応はライブラリ属性として管理し、モデル版、
  出所、収束状態、対応表をEvidenceへ含める。対応が不明なら`unknown`とする。
- ERC、DRC、router、シミュレータ、面付け、形状出力は、版、不在、非決定性を共通の
  実行記録で記録する。不在・版不明・契約不明は`unknown`で停止する。

## 10. 版管理と外部ツールの排他

**ACDの扱い：**

- 設計ファイルがテキストでも行単位マージの意味安全性は仮定しない。投影はマージせず、
  分岐・調停・復元は設計グラフ上で行い、投影を対象revisionから再生成する。
- 外部ツールがファイルを開いている間はワークツリー操作と外部ツール実行を排他にする。
  プロセス終了、ファイルハンドル解放、状態再読込を切替条件にし、中間状態を切り替えない。
- 自動バックアップ、キャッシュ、ロックファイル、生成物を版管理へ入れず、改行・文字コード差異を
  属性設定で吸収する。大きなバイナリの保管方針を別途固定する。
- 外部ライブラリは取得元URL、commit、取得時点、解決した実パスをEvidenceへ記録し、
  commit単位でpinする。「最新に追随」を既定にしない。
- 過去revisionの復元は投影再生成と再検証で行い、過去生成物を現行Evidenceとして再利用しない。
- 資格情報は別アカウント・fork・PR等の協調手段の代替にしない。最小スコープ・期限付き・共有禁止
  とし、失効・権限不足は`unknown`で停止する。

## 11. Phase 0の能力プローブ候補

次の項目は、ツール側の一次確認なしに採用しない。結果はツール版、形式版、設定hash、
入力・出力hash、実行環境、測定条件とともにEvidenceへ記録する。

**ACDの扱い：**

能力プローブの結果を工程・ツール・形式版ごとのEvidenceとして保存し、未確認項目を
成功扱いしない。実装経路の採否は[`roadmap.md`](roadmap.md)と
[`tool-selection.md`](tool-selection.md)へ反映する。

| プローブ項目 | 未確認時の扱い |
|---|---|
| 形式版の非可逆更新、旧版再読込、再保存差分 | 版混在を禁止し`unknown`で停止 |
| 隔離した設定ディレクトリ、パス変数、言語、単位の固定 | グローバル設定に依存せず停止 |
| ロックファイル検出、プロセス終了、ファイルハンドル解放 | 上書き・切替を実行しない |
| ライブラリテーブル／相対参照／環境変数の解決結果 | 実パス・版・commitが取れなければ停止 |
| ゾーン等の派生状態の再計算手段と検証への影響 | 未再計算の結果を合格扱いしない |
| variant／DNPのBOM・実装・検査出力範囲 | variantを固定できなければ停止 |
| 面付け経路、CLI契約、ライセンス、互換性、ヘッドレス可否 | 一次経路にせず継続調査 |
| 内部接続ピン、ピン電気種別、rule重大度・除外の投影可否 | 欠落を`unknown`とし抑止を許可しない |
| 検査レポートの機械可読形式と独立再読込 | 合否文字列だけをEvidenceにしない |
| GPU・表示サーバ依存機能と非描画代替経路 | 描画依存機能を既定ゲートにしない |
| 検査、router、シミュレーションの非決定性と正規化範囲 | 規則外の差分は停止 |

これらの結果は[`roadmap.md`](roadmap.md)のPhase 0完了条件と
[`tool-selection.md`](tool-selection.md)の未決事項へ還流する。
