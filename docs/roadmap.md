# ACDロードマップ

> ステータス: Draft  
> 対象: ACD固有のPhase 0〜9、初期ターゲット（1〜4層基板＋小規模筐体）

## 原則

- トレーサーバレット方式（要件から製造・実測までを貫く最小の縦切りを先に通す）。
- 借りられるものは借りる。router、CAD kernel、slicer、solver、OpenHandsを自作しない。
- 各フェーズに実機または実artifactの完了条件を置く。
- 常に出荷可能な成果物を保ち、未検証の成果物を次フェーズへ渡さない。

## フェーズ

| フェーズ | 内容 | やらないこと | 完了条件（ゴールデンタスク） |
|---|---|---|---|
| Phase 0 契約 | 電気・機械・製造・Evidenceの設計グラフschema、tool contract、event log、SDK統合骨組み | 自然言語対話、汎用最適化、自動発注 | 手書きグラフからKiCad projectを生成し、`kicad-cli` ERC/DRCとGerber出力を通る。同じグラフから筐体を生成し、CAD kernelの妥当性・干渉チェックを通る |
| Phase 1 最小一貫ループ | fixture要件→固定部品→netlist/BOM→決定論的配置＋外部router→KiCad検証→Gerber。並行して外形・高さ・connectorから筐体→干渉/clearance/肉厚→STEP/3MF | 汎用router自作、知識ベース、FW package、自動発注、自然言語入力 | 基板＋筐体を一つのfixtureから再生成できる。発注は人手 |
| Phase 2 検証ゲートと根拠 | 多段検証、Evidence、実機テスト項目の自動生成 | 協調修復の自動化、長期知識loop | 変更でstale化するEvidenceを検出し、根拠付きテスト計画を生成できる |
| Phase 3 電気↔機械協調修復 | 相互制約の反復解決、優先度・根拠・調停の記録 | 自由な要件変更、未知影響の自動無視 | 配線不能、部品高さ超過、開口不足のfixtureを両レーンで修復できる |
| Phase 4 知識ループ | fab DFM、造形不良、実測を構造化し次設計へ適用 | 未検証のLLM学習、設計データの無断共有 | 同一スコープの不良が再発しない候補ルールをEvidence付きで登録できる |
| Phase 5 要件対話とsourcing | 自然言語→構造化要件、sourcing API、データシート抽出 | 自動発注、契約判断の自動化 | 部品候補と筐体材料候補を出所付きで比較し、未確認事項を質問できる |
| Phase 6 長時間ラン運用 | task ledger、checkpoint/resume、予算、watchdog、golden task回帰 | 無制限retry、根拠なしの自動復旧 | 中断後に同じrevisionから再開し、同一入力の副作用を重複させない |
| Phase 7 FW連携と仮想実機 | FWパッケージ投影、OpenHandsによるFW実装、ピン割当整合ゲート、仮想実機（Wokwi／Renode／QEMU等は候補、採用は未決）、実機書き込みとログ取得（CMSIS-DAP／RTT、MCP経由の外部ツールは候補、要検証） | 独自コンパイラ・独自シミュレータの開発、仮想試験を実測の代替にすること | 同一設計グラフから基板・筐体・FWパッケージを生成し、FWのビルドとピン割当整合ゲートを通し、仮想実機または実機のログを測定Evidenceとして設計グラフへ記録できる |
| Phase 8 自働発注 | 基板＋部品＋実装＋送料＋税＋筐体の**総発注額**、発注前最終ゲート、API ordering | 予算超過、価格stale、契約不明の発注 | 総発注額が予算内かつ最終ゲート合格なら、承認IDなしで実行できる |
| Phase 9 ローカル製造 | 3Dプリンタ、卓上CNC、材料・機械profile、ローカル版と外注版 | 量産能力の無根拠な保証 | 同じgraphからローカル試作版と外注版を生成し、機械条件・測定Evidenceを比較できる |

フェーズ境界の変更は本表を更新し、既存のゴールデンタスクを再実行する。
